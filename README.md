# 一局人生

一个跑在浏览器里的人生模拟器。开局一张出身、三选一天赋，然后一岁一岁地活下去，直到某一年停下来。

技术栈是当前的稳定版本：**React 19 + TypeScript 7 + Vite 8**。没有后端、没有数据库、没有第三方依赖 —— 整个游戏就是一堆纯函数，跑在浏览器里。

## 跑起来

```bash
npm install
npm run dev      # http://localhost:5273
```

其他命令：

```bash
npm run build        # 类型检查 + 生产构建
npm run preview      # 预览构建产物
npm run check        # 引擎平衡自检，见下
npm run check:render # 组件渲染冒烟测试
npm run check:audit  # 内容审计：找那些不会崩、只会让游戏悄悄变味的问题
```

## 它是什么样的游戏

五个属性：智力、体质、魅力、财富、快乐。体质归零就死了，所以它同时是血条。

一岁推进一次，每年抽一个事件。有的要你选，有的只是叙述。**选择是有代价的**：钱、身体、快乐，很少能同时要。

三件事决定了它不只是个随机数生成器：

- **天赋带标签，标签会跟着你一辈子。** 「书香门第」不只是初始智力高一点，它会让你在后几十年的条件判断里反复被抽到。
- **年龄本身会做事。** 四十岁以后身体开始按年计息，年轻时则会自己恢复。所以「寿终」和「垮掉」是两条赛跑的死法。
- **结局是从你的一生里长出来的。** 称号先看你做过什么（标签），再看你最后成了什么样的人（最高属性）。墓志铭同理。

## 确定性

整个游戏只依赖一个 32 位的随机数状态。**同一颗种子 + 同一串选择，永远得到同一段人生。**

所以：

- 地址栏会同步 `?seed=12345`，把链接发给别人，对方面对的是同一副牌；
- 存档存的就是这个游标，刷新页面接着活；
- 结局页可以「用同一颗种子再来一次」，看看换一种选法会怎样。

## 引擎自检

`npm run check` 会跑 800 局 ×2（一种瞎选、一种认真选），然后检查：

- 每一局都能正常结束，不会卡在某个年龄；
- 属性永远落在 0-100，且不是 NaN；
- **认真选的成绩要明显好过瞎选。**

最后一条是真正的验收标准。如果两种打法的结果差不多，说明选择没有意义，那这个游戏就白做了。当前结果：

| 打法 | 平均评分 | 主要死因 | 评级集中区 |
|---|---|---|---|
| 瞎选 | 56.6 | 寿终 59% / 健康崩塌 34% | B、C |
| 认真选 | 71.5 | 寿终 85% | A |

## 加内容

加事件只需要在 `src/engine/events/` 里对应的阶段文件中追加一个对象：

```ts
{
  id: 'startup',
  kicker: '二十六岁',
  minAge: 24,
  maxAge: 29,
  weight: 10,                                  // 权重，越大越常见
  cond: (s) => s.stats.intellect > 45,         // 不满足就不会进池
  text: '朋友拉着你说，一起做吧，稳赚不赔。',
  options: [
    { label: '押上全部积蓄', risk: 32,
      fx: { wealth: 30, joy: 8 },
      fail: { fx: { wealth: -26, joy: -12 }, text: '两年后项目停了。' },
      text: '第三年你们卖掉了公司。' },
  ],
}
```

`risk` 是成功率百分比，失败走 `fail` 分支。`auto: true` 表示纯叙述、不需要选择。改完跑一遍 `npm run check` 看看平衡有没有被带偏。

## 已知的小问题（没改，等你决定）

- **高考的「低分线」几乎是死内容。** `gaokao-low` 要求 18 岁时智力 < 38，但实测 18 岁智力中位数是 59、最低也有 27 —— 三千局里只有 0.4% 能走到「读专科 / 直接进社会」那两条路。想把这三条线摊匀，阈值要从 38 提到 46 上下。
- **复制分享文案依赖 `navigator.clipboard`**，它只在 https 或 localhost 下可用。纯 http 打开时按钮会安静地什么都不做。
- `EVENT_INDEX`、`isZeroDelta`、`Rng.shuffle` 目前没有调用方，属于预留 API。

## 后面可以做什么

现在是纯规则版。要接 AI，只需要替换 `drawEvent()` 这一个函数：把「从池子里按权重抽」换成「问模型」，其他的状态机、结算、结局逻辑都不用动。这也是当初把它设计成纯函数的原因。
